# Parallel Chat Streaming Implementation

## Overview

Implemented parallel chat streaming and visual indicators, matching Paprwork v1's behavior where multiple chats can stream simultaneously with real-time status indicators.

## Features Implemented

### 1. ✅ Empty Chat Detection

**Problem**: Creating multiple "New Chat" tabs when one is already empty clutters the interface.

**Solution**: 
- `handleNewChat()` now checks for existing empty chat tabs
- If an empty chat exists (0 messages), switches to it instead of creating new
- Only creates new chat if no empty chats are available

```typescript
const existingEmptyChat = tabs.find(
  (tab) =>
    tab.type === "chat" &&
    messages.length === 0 &&
    tab.id === `chat-${activeChat}`,
);

if (existingEmptyChat) {
  switchToTab(existingEmptyChat.id);
  return;
}
```

### 2. ✅ Distinct Chat IDs for Parallel Streaming

**Each chat has a unique ID**:
- Chat ID format: Generated by backend (UUID or timestamp-based)
- Tab ID format: `chat-{chatId}`
- Entity ID: Stored in `tab.entityId`

**Parallel State Management**:
```typescript
interface ChatStore {
  // Per-chat state (keyed by chatId)
  chatStates: Map<string, ChatState>;
  
  // Each chat has independent state
  interface ChatState {
    messages: ChatMessage[];
    isLoading: boolean;
    isSending: boolean;
    isStreaming: boolean;
    hasUnread: boolean;
  }
}
```

### 3. ✅ Visual Indicators (Dots)

**Green Pulsing Dot** (Streaming):
- Shows when agent is actively streaming in that chat
- Animated pulse effect (2s cycle)
- Only visible on inactive tabs

**Blue Solid Dot** (Unread):
- Shows when chat has new messages that haven't been viewed
- Disappears when user switches to that tab
- Only visible on inactive tabs

**CSS Implementation**:
```css
.tab__indicator--streaming {
  background: #34c759;
  animation: pulse 2s ease-in-out infinite;
}

.tab__indicator--unread {
  background: #007aff;
}
```

### 4. ✅ Parallel Streaming Support

**How it works**:

1. **Multiple chats can stream simultaneously**:
   - Each chat maintains its own `ChatState` in the map
   - Streaming state tracked per-chat: `chatStates.get(chatId).isStreaming`
   - Messages updated in correct chat, even if not active

2. **Background updates**:
   - Chat A is active, user is viewing it
   - Chat B receives new message → marked as `hasUnread: true`, blue dot appears
   - Chat C is streaming → `isStreaming: true`, green pulsing dot appears
   - All updates happen in parallel

3. **State synchronization**:
   ```typescript
   addMessage: (message, chatId) => {
     const targetChatId = chatId || activeChat;
     
     // Update chat state map
     chatStates.set(targetChatId, { ...state, messages: [...messages, message] });
     
     // If not active, mark as unread
     if (targetChatId !== activeChat) {
       chats = chats.map(chat => 
         chat.id === targetChatId 
           ? { ...chat, hasUnread: true } 
           : chat
       );
     }
   }
   ```

### Colors (Liquid Glass):
- **Light mode**:
  - Streaming: `#34c759` (Apple green)
  - Unread: `#007aff` (Apple blue)
- **Dark mode**:
  - Streaming: `#30d158` (brighter green)
  - Unread: `#0a84ff` (brighter blue)

### Animation:
- Pulsing effect for streaming (50% opacity at midpoint)
- No animation for unread (solid)
- 2s duration, ease-in-out timing

## Tab Behavior

### Active Tab:
- No indicator shown (you're viewing it)
- Automatically marks chat as read

### Inactive Tabs:
- Show streaming indicator if agent is responding
- Show unread indicator if has new messages
- Priority: streaming > unread (only one shows)

### Tab Creation:
- Each chat gets unique tab with distinct entityId
- Tab title updates when chat gets first message
- Tabs can be merged (split view) while maintaining separate streaming states

## Usage Example

```typescript
// User workflow:
1. User creates Chat A, asks question
   → Chat A tab shows green pulsing dot (streaming)
   
2. User switches to Chat B (already open), asks question
   → Chat A tab shows blue dot (has unread response)
   → Chat B tab shows green pulsing dot (now streaming)
   
3. User creates Chat C, asks question
   → Chat A: blue dot (unread)
   → Chat B: blue dot (unread)
   → Chat C: green pulsing dot (streaming, active)
   
4. User switches back to Chat A
   → Chat A: no dot (now active, marked as read)
   → Chat B: blue dot (still unread)
   → Chat C: blue dot (response came in while on Chat A)
```

## Backend Integration

### WebSocket Messages:

The Gateway should send chat-specific updates:

```typescript
// Streaming update
{
  type: "chat:stream",
  chatId: "chat-uuid-123",
  messageId: "msg-456",
  content: "partial response..."
}

// Stream complete
{
  type: "chat:stream-complete",
  chatId: "chat-uuid-123",
  messageId: "msg-456"
}

// New message (background chat)
{
  type: "chat:message",
  chatId: "chat-uuid-789",
  message: {...}
}
```

### Store Integration:

```typescript
// In useAgent or WebSocket handler:
websocket.on('chat:stream', (data) => {
  updateStreamingMessage(data.messageId, data.content, data.chatId);
  setChatStreaming(data.chatId, true);
});

websocket.on('chat:stream-complete', (data) => {
  finalizeStreamingMessage(data.messageId, data.chatId);
  setChatStreaming(data.chatId, false);
});
```
